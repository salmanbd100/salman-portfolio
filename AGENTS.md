# This project

Next.js 16 App Router with Turbopack, React 19, Tailwind v4, shadcn on
`@base-ui/react`. Deployed on Vercel.

**pnpm.** There is a `pnpm-lock.yaml`; never run `npm` or `yarn` here.

**Verification** — there is no test suite, so these three are the whole gate:

```bash
pnpm build          # also the only check on post metadata
pnpm lint
npx tsc --noEmit
```

**Every route must stay static.** `pnpm build` prints a route table; a `ƒ`
(Dynamic) next to any route is a regression, not a detail. It means something
leaked a request-time dependency and the SEO benefit of that page is gone.

## The blog

MDX files in `content/blog/`, compiled at build. `lib/blog/posts.ts` is the only
module that touches the filesystem — keep it that way, so swapping to a CMS later
is one file.

Design record, including what the original design got wrong:
`docs/superpowers/specs/2026-08-11-tech-blog-design.md`.

### Traps that have already cost time

**Do not add a remark/rehype plugin whose options contain functions.** Turbopack
cannot marshal them to Rust. This rules out `rehype-pretty-code` and
`@shikijs/rehype` — their `transformers` option is an array of functions.
Highlighting therefore lives in `components/blog/code-block.tsx`, a Server
Component calling Shiki directly. Only string-form plugins with serializable
options work in `next.config.ts`.

**Local plugins need an absolute path** in `next.config.ts`. `@next/mdx`
resolves plugin strings with `require.resolve(spec, { paths: [projectRoot] })`,
and Node ignores `paths` for relative specifiers.

**Posts use `export const meta`, not YAML frontmatter.** `@next/mdx` has no
frontmatter support. `lib/blog/schema.ts` validates it: structural problems throw
and fail the build, soft SEO limits only warn.

**Fence meta lands on hast `data`, not `properties`,** so `title="…"` and
`{2-3}` never reach the component as props. `lib/blog/rehype-code-meta.mjs`
copies it across. Only `properties` becomes JSX props.

**Metadata image routes need their own `generateStaticParams`.**
`opengraph-image` and `twitter-image` are separate route handlers; without it
they stay dynamic even when the page is static. Also: `runtime = "edge"`
disables static generation, so don't add it to an image route.

**Drafts gate on `VERCEL_ENV`, not `NODE_ENV`.** Vercel previews build with
`NODE_ENV=production`, which would hide drafts exactly where they need review.

**File-based metadata overrides `generateMetadata`,** and Next replaces a
metadata field wholesale when a child route defines it — which is why
`blogAlternates()` in `lib/blog/metadata.ts` exists instead of inline objects.

### Writing a post

Use the `write-blog-post` skill in `.claude/skills/`. It covers the house style
(simple English, 600–1000 words, diagrams where they earn their place).

Always scaffold with `pnpm new-post "Title"` — it stamps today's date, and a
wrong date silently sorts the post to the wrong place in the index and the feed.
Never flip `draft: false` unless asked.

## Styling

**One palette, in `app/globals.css`.** Warm off-white surfaces (`bg`, `bg2`,
`bg3`, `quote`) with a teal accent, shared by the blog and the portfolio. Use the
tokens; do not hardcode hex values in components. `--color-ink3` is pinned to the
value that clears 4.5:1 on the page background — check contrast before changing
any text colour.

**Two type scales.** The site runs at `0.9375rem` because it is UI, scanned in
seconds. Blog prose uses the `text-prose` / `text-prose-lg` tokens (17px on
phones, 19px from 48rem) because it is read for minutes. Line heights ride along
with those tokens.

**Two heading faces.** `font-editorial` (Newsreader) is blog headings only;
`font-serif` (Space Grotesk) is everything else. That contrast is deliberate.

Prose styling is hand-written in `mdx-components.tsx` rather than
`@tailwindcss/typography` — the plugin's defaults would need more overriding than
the rules cost to write.

Measure caps at `56ch`, set on `<article>` alongside the prose font-size, because
`ch` resolves against the element's own font-size.
